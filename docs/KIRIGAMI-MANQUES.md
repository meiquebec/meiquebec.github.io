# Ce qui manque à Kirigami

Points relevés pendant l'audit, à régler dans le monorepo
`php-kirigami/kirigami` (et à reporter dans son `docs/ROADMAP.md` /
`docs/TODO.md`). K7, K8 et K9 (galeries) sont publiés (php-wasm 8.5.11-4,
php-prepros 3.2.5, Kiri Studio 0.5.4) ; K3, K11 et K12 (comités en direct
dans l'aperçu de Studio) sont faits et attendent core 3.2.9 et Kiri Studio
0.5.5 ; les autres ont un contournement documenté ici.

| # | Manque | Effet sur ce site | Contournement actuel | Proposition |
|---|---|---|---|---|
| K8 | ✅ **Publié le 2026-10-02 (php-wasm 8.5.11-4).** Un bloc de plugin Markdown ne pouvait pas contenir d'autres codes `{% … %}` : `mdhtml` fermait le bloc au premier `%}` | Impossible d'écrire une galerie comme une suite de codes `{% img-asset %}` | — | `php-mdhtml` 0.1.6 : le bloc se ferme sur le `%}` qui équilibre son `{%` ; corps transmis brut. Reste : tag `v0.1.6`, rebuild de `@kirigami/php-wasm`, publication |
| K7 | ✅ **Publié le 2026-10-02 (php-prepros 3.2.5).** `IMG::asset()` renvoyait un chemin non encodé (espaces, parenthèses) | Les `src` des photos de téléphone contenaient des espaces | — | php-prepros : URL encodée segment par segment ; noms sur disque inchangés (Sass et plugins média gardent la même convention). Test `test/asset-url.test.js` |
| K9 | ✅ **Publié le 2026-10-02 (Kiri Studio 0.5.4).** Kiri Studio insérait `{% img-asset photo (1).jpeg 800 %}` sans guillemets ; l'argument était coupé à l'espace | Une photo au nom avec espace cassait le code | — | Kiri Studio : chemin entre guillemets dès qu'il contient un espace ou un guillemet (`imageCode()`, testé) |
| K1 | Les scripts (`runenv`) ne voient pas les variables d'environnement du processus | La clé de géocodage ne peut pas venir directement d'un secret GitHub | La CI écrit `secrets.local.yaml`, monté par `mount:` | `scripts[].env: [GEOCODING_API_KEY]` : liste blanche de variables passées au PHP (`getenv()`), jamais tout l'environnement |
| K2 | `prepros.network` est un seul interrupteur pour le rendu **et** les scripts | Activer le réseau pour le géocodage l'active aussi pour toutes les pages | Accepter `network: true` | `scripts[].network: true` indépendant de `prepros.network` |
| K3 | ✅ **Corrigé le 2026-10-02, à publier (core 3.2.9).** Le watch (`kiri serve` / `kiri watch`, aperçu de Studio) ne relançait jamais les scripts `before-build` | Un comité ajouté n'avait ni épingle ni logo dans l'aperçu | — | `scripts[].watch: [globs]` : le script est relancé quand un de ces fichiers change, puis tout le site est re-rendu s'il a écrit des fichiers. Testé en direct sur ce site |
| K11 | ✅ **Corrigé le 2026-10-02, à publier (core 3.2.9).** Le chargeur de `kirigami.yaml` remplaçait par leur contenu les chemins de `scripts[].mount` / `watch` qui nomment un `.yaml` / `.json` existant | `mount: [secrets.local.yaml]` aurait monté… le contenu des secrets, en CI ; `watch: [comites.yaml]` était refusé | — | `mount` et `watch` sont repris de la lecture brute, comme `studio:` (test ajouté) |
| K12 | ✅ **Fait le 2026-10-02, à publier (Kiri Studio 0.5.5 + schéma du core 3.2.9).** L'aperçu de Studio n'avait aucun moyen d'obtenir une clé, ni de publier ce que les scripts calculent | Pas de géocodage dans l'aperçu ; la CI devait tout refaire, avec le risque de blocage Instagram | — | `studio.secrets` (clé saisie dans « Clés du site », chiffrée sur le poste, écrite dans la copie d'aperçu) et `studio.publish` (fichiers générés pris dans l'aperçu au moment de publier) |
| K10 | Les ancres des titres perdent les lettres accentuées (`mdhtml`, ancres ASCII seulement) | « Rêver le pays » → `#rver-le-pays` (avant : `#rêver-le-pays`) ; un lien vers l'ancienne ancre casse | Aucun lien interne ne les utilise | Translittérer (ou garder en UTF-8) dans `php_mdhtml_slugify()` — déjà dans la TODO de `php-mdhtml` |
